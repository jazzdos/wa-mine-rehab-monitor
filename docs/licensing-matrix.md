# Licensing matrix

This is the repository's data-licence deliverable, per the design doc
(`docs/plans/2026-08-15-wa-mine-rehab-monitor-design.md` §6/§8). There is no
single repository-wide data licence: every external source carries its own
licence assignment, pinned in code at `src/wa_mine_monitor/licence.py`
(`SOURCES`) and reproduced here per source. This file is generated by hand
from that module; if the two ever disagree, `licence.py` is authoritative —
run `uv run pytest tests/test_licence.py` before trusting a change to either.

## Code licence

Original code in this repository is **MIT** (`LICENSE`). Modules ported from
the `jarrah-rehab` project retain an origin-commit header naming the exact
source commit they were copied from — same author, MIT-relicensed on port,
not a separate licence grant. See, for example, the header on
`src/wa_mine_monitor/export_gate.py`, `src/wa_mine_monitor/provenance.py` and
`src/wa_mine_monitor/secrets.py`:

> Ported from jarrah-rehab `src/jarrah_rehab/reporting/export.py` at commit
> `cf1743e202d367fcb2016eca0a1563b4f9db240c` (2026-08-15); MIT-relicensed by
> the same author.

The project's own MIT licence never implies anything about the licence of
the *data* any module reads or writes — the table below is the only
authority for that.

## Snapshot policy

Every source above is consumed as a **dated snapshot**: a fetch is pinned to
the date it was captured (`SourceAsset.snapshot_date` in
`src/wa_mine_monitor/provenance.py`), never re-derived silently on a rerun.
A run manifest records the exact snapshot each source asset came from, so
"which version of the outside world a run saw" is always reconstructible.
DEA collections are versioned STAC collections read at fetch time; DMIRS-001,
DMIRS-003 and DBCA-060 are Data WA catalogue extracts pinned to the extract
date; Maus v2 is the fixed PANGAEA DOI above (no rolling "latest" pointer);
Hansen GFC is pinned to the named product version (`GFC-2024-v1.12`); SILO is
fetched as whole annual gridded NetCDF objects (`<year>.daily_rain.nc`) from
the anonymous open-data bucket.

## Transformation notice

Every derived artefact this project publishes is a **transformation** of the
sources above, not a redistribution of the source files themselves — a
per-site spectral chronology, a statewide register, a zonal statistic, a
crosswalk. Where a source's own licence requires it (CC-BY, CC-BY-SA), the
transformation is disclosed in the artefact's own attribution text, and any
CC-BY-SA-derived package states its modifications per the ShareAlike grant
rather than presenting them as an unmodified copy.

## Redistribution decisions, in full

- **Clean (CC-BY-4.0, `redistribute_public=True`):** the three DEA geomedian
  collections, DEA Fractional Cover Percentiles, DMIRS-003 Mining Tenements.
  Read from each source's own licence field (a STAC collection's `license`
  key, or Data WA's `license_id`), never inferred from the operating agency.
  SILO Climate Database is also in this group: this project consumes SILO's
  GRIDDED product as whole annual NetCDF objects from the anonymous AWS
  open-data bucket (`s3://silo-open-data`, ap-southeast-2), CC BY 4.0, no
  account and no credential on that route. The account-gated point/Data
  Drill API is a different SILO product and is not used here.
- **Fail-closed (`redistribute_public=False`):** DMIRS-001 MINEDEX. Data WA's
  catalogue record for `minedex-dmirs-001` states `license_id: cc-nc`
  (CC-BY-NC-4.0). WA's Digital Atlas of Sustainability and Conservation
  (DASC) separately carries a blanket "unless otherwise noted" CC-BY-4.0
  statement — and the Data WA catalogue label **is** such a note, so it
  cannot be read as overridden by the blanket statement. `SOURCES["dmirs_001_
  minedex"]` is pinned `redistribute_public=False` unconditionally; nothing
  in `licence.py` ever flips that static registry entry.

  **D7-adjudicated (2026-08-16).** Every DASC bundle carries its own
  `Licence_CCBY4.pdf`, explicit evidence of a CC-BY-4.0 grant. The delegated
  director's D7 ruling
  (`docs/decisions/2026-08-16-d6-d8-dasc-acquisition-and-minedex-licence.md`)
  weighed that evidence against the Data WA `cc-nc` label and kept MINEDEX
  redistribution closed: an official government catalogue record is not
  "third-party commentary" a bundled PDF's "unless otherwise noted" clause
  can override. The `adjudicate-minedex-licence` CLI command applies this
  ruling to an already-finalized snapshot's `licence_evidence.json`
  (`explicit_grant: "CC-BY-4.0"`, `contrary_notice: true`,
  `adjudicated: true`), never to the source registry entry above. That
  rewrite also re-signs the evidence JSON's one line in the snapshot's
  `SHA256SUMS.txt`, which retires the digest `fetch-minedex`'s run manifest
  pinned under `output.sha256`; the command therefore writes its own run
  manifest beside `licence_evidence.json`, carrying the before/after sha256
  of both files it changed and a `supersedes_manifest` pointer back to
  `SHA256SUMS.txt.run_manifest.json`. The two manifests read together are
  what distinguish a correctly adjudicated snapshot from a tampered one.

  A **separate, narrower** mechanism governs whether one run's captured
  MINEDEX evidence can unblock a public *export*:
  `licence.minedex_redistribution_allowed(evidence_dir)` returns `True` only
  when `evidence_dir/licence_evidence.json` exists, parses as a JSON object,
  and states `explicit_grant == "CC-BY-4.0"`, `contrary_notice is False`
  (exactly, not merely falsy), and a non-empty `evidence_files` list naming
  what was captured. Any parse error, missing file, missing key, or
  wrong-typed value returns `False` — fail-closed, never raises. Post-D7,
  every adjudicated snapshot carries `contrary_notice: true`, which is
  exactly what keeps this gate returning `False`: the ruling closed the
  conflict, it did not resolve it. This function never mutates the registry
  entry above; it is the evidence gate `fetch-minedex` /
  `adjudicate-minedex-licence` / any future `export-release` CLI path checks
  before treating MINEDEX-derived attributes as anything other than
  internal-only. The written-clarification route (emailing DMIRS to ask) is
  unavailable under this project's standing directive against external
  data-request emails — resolution can only come from a captured,
  resource-specific document, not a request.

  **Superseded acquisition route (historical).** Both DMIRS-003 and
  DMIRS-001 were originally pinned to Data WA / SLIP direct-download
  GeoPackage endpoints
  (`https://data-downloads.slip.wa.gov.au/DMIRS-003/Geopackage` and
  `.../DMIRS-001/Geopackage`). Both were measured auth-gated on 2026-08-16
  (Task 11 live acceptance run): each returns a Landgate SSO login page
  (`sso.slip.wa.gov.au`), not data. The D6 ruling in the same decisions doc
  replaced both with the unauthenticated DASC bundle route recorded in the
  table above; the SLIP URLs remain recorded here, and as a comment in
  `src/wa_mine_monitor/sources/tenements.py` /
  `src/wa_mine_monitor/sources/minedex.py`, rather than removed silently.

- **Share-alike, published separately (CC-BY-SA-4.0,
  `redistribute_public=True`):** Maus et al. v2 mine polygons. ShareAlike
  applies to the *whole* Maus-derived package (WA extract, crosswalk,
  trajectories over the Maus mask), applied conservatively — no scalar-field
  carve-outs are asserted. That package publishes as its own separate
  artefact under CC-BY-SA-4.0 with attribution, source link and modification
  statement; it is never folded into the project's MIT-licensed code or into
  a CC-BY export built from another source. **Stated exactly, because an
  overclaim here is the same failure shape CLAUDE.md names repeatedly:**
  `export_gate.py`'s geometry drop makes the GEOMETRY half of this
  structural — any frame passed through `export_public` has every
  geometry-bearing column removed by name or by value, so Maus-derived
  geometry cannot leak into a non-Maus export by accident. It does **not**
  make the SCALAR half structural. `SOURCES["maus_v2"].redistribute_public`
  is `True`, so a Maus-derived scalar column (a crosswalk id, an area, a
  trajectory statistic) passes `export_public`'s row gate exactly like any
  other CC-BY-SA-permitted row and is dropped only if its name or value
  independently reads as geometry — nothing in `export_gate.py` currently
  distinguishes "CC-BY-SA scalar" from "CC-BY scalar". Keeping Maus-derived
  scalars out of a non-Maus CC-BY export today is therefore a project-level
  packaging discipline (never assembling such a frame), not something the
  gate itself enforces. Closing that gap needs either a `share_alike` field
  on `SourceLicence` with a mixed-provenance refusal in the export path, or a
  per-row source/licence provenance column checked at the boundary; neither
  exists yet, so this paragraph states only what the code does today.
- **Conditional (CC-BY-4.0, `redistribute_public=True`):** Hansen GFC — see
  "Hansen credit strings" below.
- **Open, context-only (`redistribute_public=True`, restricted use):**
  DBCA-060 Fire History. The fire record is incomplete statewide and its own
  metadata says it can include burns inside mining-rehabilitation areas, so
  "not recorded" is never treated as a known-negative fire label — every
  site-year this project derives from it carries `fire_status ∈ {recorded,
  not_recorded, unknown}`, never a bare boolean. Licence corrected from the
  provisional "open" 2026-08-29 to CC-BY-4.0: CKAN dataset
  `3ce8a891-b050-4c38-952b-c40ca8bdc042` records `license_id: cc-by`
  (jarrah-verified 2026-07-20), evidenced by a digested capture of the
  catalogue page (`docs/decisions/2026-08-29-dbca-mirror-declined.md`).

## Hansen credit strings

Hansen/UMD/Google/USGS/NASA Global Forest Change (`GFC-2024-v1.12`) is
CC-BY-4.0, conditional on attaching **both** of its two credit strings — they
are not interchangeable, and one substituting for the other does not satisfy
the grant:

- **Display string**, wherever the data are shown:

  > Source: Hansen/UMD/Google/USGS/NASA

- **Citation string**, wherever the source is cited in text:

  > Hansen, M. C., P. V. Potapov, R. Moore, M. Hancher, S. A. Turubanova, A.
  > Tyukavina, D. Thau, S. V. Stehman, S. J. Goetz, T. R. Loveland, A.
  > Kommareddy, A. Egorov, L. Chini, C. O. Justice, and J. R. G. Townshend.
  > 2013. "High-Resolution Global Maps of 21st-Century Forest Cover Change."
  > Science 342 (15 November): 850–53. Data available on-line from:
  > https://glad.earthengine.app/view/global-forest-change.

## Tier 0 public-RC packages

The public repository's release candidate ships two standalone reference
layers in place of the private, D7-closed internal MINEDEX monitoring
frame. Neither package carries a crosswalk to that frame or any MINEDEX
lineage: each is a direct extract of its own upstream source, licensed and
attributed independently, with owners recorded from the source register as
owners only, never as operators (D8).

- **`tier0-tenements`** — Mining Tenements (DMIRS-003) extract. Source:
  https://catalogue.data.wa.gov.au/dataset/mining-tenements-dmirs-003, via
  the DASC bundle route recorded above. Licence: **CC-BY-4.0**, the same
  grant as the source row's public licence state in the table above.
- **`tier0-maus-wa`** — the WA extract of Maus et al.'s global mining
  polygons, v2. Source: https://doi.pangaea.de/10.1594/PANGAEA.942325.
  Licence: **CC-BY-SA-4.0**, carrying its own modification statement per
  the ShareAlike grant, published as its own separate artefact rather than
  folded into a CC-BY export.

Each package's licence is tracked and satisfied independently; nothing in
either package is derived from, or requires, the internal MINEDEX frame.

`SOURCES["hansen_gfc"].attribution_text` carries both strings, separated by a
blank line, so a caller rendering the whole field satisfies the grant either
way. Unresolved and not adopted: the source page's own prose states
`lossyear` has "range 1-20" while the product claims 2001–2024 coverage — a
source-internal inconsistency, so any year bound this project reports is
verified empirically against the granule, never read off the page alone.

## Source

Every field above is pinned in `src/wa_mine_monitor/licence.py` (`SOURCES`)
as measured on 2026-08-15 against the primary record named in each row's
"Exact resource" column — per CLAUDE.md's sourcing rule, the exact resource
is read directly, never inferred from the operating agency's general
reputation. `tests/test_licence.py` asserts every entry carries a non-empty
`source_url`, `licence_id` and `attribution_text`, and that the MINEDEX entry
stays pinned closed and conflicted, and that the Hansen entry carries both
credit strings.
